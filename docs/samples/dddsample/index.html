Dependency Graph of project

How to read this graph

  1. Each label on the ring is a Maven module (artifactId; hover for the full groupId and level). Modules with the same groupId sit together, marked by a grey arc. The project itself, the project, is shown in blue.
  2. Each line is a dependency from a module to a module it declares in its POM.
  3. Hover a module to trace it. Incoming lines show who uses it: directly or indirectly. These modules may be affected if it changes. Outgoing lines show what it needs: directly or indirectly.
  4. Pick a module to focus on it. All modules shows the whole project, including how its modules depend on each other. Choosing one module redraws the chart for that module alone, and Depth then counts from it.
  5. Use Depth to peel the graph in layers. L1 shows only the project's direct dependencies; each further level adds the dependencies of the previous one. Start at L1 and step up with + to see where transitive dependencies come from.
  6. Look for hotspots. Modules with many incoming lines are hubs: upgrading them ripples through the graph. Modules with many outgoing lines pull in a lot. The statistics below rank them; hover a table row to find it in the graph.

Rated columns are shaded by how each value ranks within its column: the best fifth of values are dark blue, the next fifth light blue, the middle grey, then light red, and the worst fifth dark red. Hover a cell to see its band. Columns without an arrow, such as instability on its own, have no better direction and are not shaded.

Coupling by module

Ca
afferent coupling: modules that depend on it directly
Ce
efferent coupling: modules it depends on directly
I
instability = Ce / (Ca + Ce): 0 is depended on and stable, 1 only depends on others
Impact
modules that depend on it directly or indirectly
Footprint
modules it pulls in directly or indirectly

Cohesion by group (groupId)

Internal
dependencies between modules of the same group
Ca / Ce
dependencies coming into / going out of the group
H
relational cohesion = (Internal + 1) / Modules: higher means the group's modules work more closely together
Internal share
Internal / (Internal + Ce): share of the group's dependencies that stay inside it
—
cohesion does not apply to a group with a single module; those groups are left out of the H and Internal share ranking

These are module-level (package-level) metrics computed from Maven metadata. They are not the Chidamber & Kemerer (CK) suite: CK metrics such as coupling between objects (CBO) and lack of cohesion in methods (LCOM) are measured per class and need bytecode analysis, so they are not included.
